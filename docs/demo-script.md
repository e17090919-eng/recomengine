# 演示脚本：Isle Select 演示商城

一个“假客户”电商网站，所有推荐都来自我们的推荐引擎。商城后端只通过正式接口和 Python SDK
（`recsys_client`）调用引擎，签名、请求 ID、页面位置编码（spm）、埋点都按真实接入的方式来，
所以它也可以当作 CDF 接入时的参考代码（`apps/demo-shop/src/demo_shop/app.py`）。

商品、品牌、用户都是模拟数据，不涉及任何真实品牌。

## 启动

```bash
make demo
```

- 商城：http://127.0.0.1:8100
- 引擎配置后台：http://127.0.0.1:8000/admin

第一次运行时，如果没有模拟数据或模型，会先自动生成数据并训练，需要几分钟。
按 Ctrl-C 同时停止两个服务。

演示期间产生的行为写入 `lake_demo/`，不会污染训练数据 `lake/`。配置后台使用独立的
`artifacts/demo-config.db`，每次 `make demo` 都会从 `configs/engine.toml` 重新开始。

**每次演示前点一下右上角的「重置演示」**：清空实时行为、购物车和本次下的订单，
保证每次都从同一个状态开始。

## 流程（约 6 分钟）

**0. 开场（30 秒）**
打开「讲解模式」，告诉大家：商品卡片下面的蓝色标签是推荐理由（哪一路召回出来的），
右侧是“引擎眼中的 TA”和这次接口调用的耗时、实验分组。

**1. 冷启动 → 实时反应（1 分钟）**
- 选「新访客」：首页标签都是「热门」，右侧画像是空的。
- 点「香水」类目，连续打开 3 个香水商品。每个商品页下面的「看了又看」也是香水。
- 回到首页：20 个推荐里大约一半变成了香水，标签变成「兴趣 / 口味相近 / 相似用户也喜欢」；
  右侧偏好类目出现香水。
- 要点：**点击后下一次请求就生效，不用等第二天的批处理。**

**2. 千人千面（1 分钟）**
- 切换到「护肤达人」：首页完全不同，以护肤彩妆为主。
- 切换「实验组」control / treatment，说明两组用的排序模型不同（召回分数 vs GBDT），线上按用户哈希自动分组。

**3. 多市场（1 分钟）**
- 顶部把市场切到「奥克兰机场免税」：币种换成 NZD，语言换成英文，只展示这个市场有货的商品。
- 要点：**市场、币种、语言、限购、禁售都是配置，不是代码。**

**4. 免税额度（1 分钟）**
- 切换到「额度快用完的高端客」，打开购物车：今年已用 ¥85,738，剩 ¥14,262。此时搭配推荐里还有几千元的手表。
- 去「腕表」类目，把一块一万多的表加入购物车，再回购物车：剩余额度只有几百元，
  搭配推荐自动换成了几百元以内的护肤品。
- 要点：**推荐不会出现用户结不了账的商品。**

**5. 复购（30 秒）**
- 切换到「该补货了」，进「我的订单」：上面是“该补货了”，下面是 TA 3 到 4 周前的订单。
- 要点：引擎从数据里学出每个类目多久会再买一次，到时间就提醒。

**6. 运营现场改配置（1 分钟）**
- 新开一个标签页打开 http://127.0.0.1:8000/admin。在「栏位」里给 `home_feed` 的物品池排除一个品牌
  （比如首页正在推的某个品牌），先点「预览」看前后对比，再填说明点「发布」。
- 回到商城首页点「换一批」：5 秒内这个品牌就不见了。再在「版本」里一键回滚。
- 要点：**运营可以自己改规则，有预览、审计和回滚，不需要发版。**

**7. 效果（1 分钟）**
- 切换到「烈酒爱好者」，打开「效果对比」：左边是热销榜（近似现有做法），右边是推荐引擎。
  看两边的“与 TA 兴趣相符”：0/20 对比 10/20 以上。
- 再展示 A/B 模拟日报（`make ab-sim`，生成在 `reports/`）：新西兰点击率 +28%，中国 +6%，人均 GMV 分别 +53%、+26%。
  **要说明这是模拟数据**，真实效果要在 CDF 线上用 5% 流量做 A/B 才能确认。

## 可能被问到的

- **“这些推荐是写死的吗？”**
  不是。打开讲解模式，看推荐理由和接口耗时；也可以现场换一个用户，或者点几个别的类目。
- **“引擎挂了怎么办？”**
  可以现场停掉引擎（Ctrl-C 之后单独启动商城：`uv run demo-shop`）。SDK 会返回商城提前给的兜底列表（热销榜），
  讲解模式会提示“SDK 用了兜底列表”。
- **“接入要做什么？”**
  参考 `apps/demo-shop/src/demo_shop/app.py`：推荐调用 `predict`，埋点调用 `write`，
  把返回的 `request_id` 和 `spm` 带到点击、加购事件里就行。下单时可以不带，引擎会把订单归到 72 小时内的最后一次点击。

## 已知限制

- 数据是模拟的，“今天”是模拟数据最后一天往后推，订单显示的是相对时间。
- 讲解模式的用户画像、演示重置用的是引擎的调试接口（`/demo/*`）。重置只在 `RECSYS_DEMO=1` 时可用，生产环境不开放。
- 首页每次请求都会避开 30 分钟内已经推过的商品，所以「换一批」每次都不一样，这是正式逻辑。
