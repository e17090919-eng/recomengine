# 埋点与坑位规范（Tracking & SPM Spec）v0.1

> 用途：P0 阶段与客户（首个为 CDF）对齐埋点，作为客户端、数据团队和推荐引擎三方的共同约定。
> 字段最终落到的标准表结构见 [`data-contract.md`](data-contract.md)。已有埋点不需要改名：字段对应关系写在 `configs/mappings/<客户>.toml` 里，由回灌工具 `recsys backfill` 转换。

## 1. 必须上报的行为

| 标准 event_type | 触发时机 | 必带属性 | 用途 |
|---|---|---|---|
| `impression` | 商品卡片**可见面积 ≥ 50% 且持续 ≥ 1 秒**；同一次请求、同一个商品只报一次 | item_id、spm（含位置）、request_id | 计算 CTR 的分母，训练排序模型。**缺了它就没法训练点击率模型** |
| `click` | 进入商品详情页 | item_id、spm、request_id | 正样本 |
| `favorite` | 收藏 | item_id | 兴趣信号 |
| `add_cart` | 加入购物车 | item_id、quantity | 转化信号、凑单推荐 |
| `order_submit` | 提交订单（未支付） | item_id、quantity | 漏斗 |
| `purchase` | **支付成功**（以服务端回调为准） | item_id、quantity、paid_amount、currency | 转化、GMV、已购过滤、额度扣减 |
| `dislike` | 点了"不感兴趣" | item_id | 负反馈 |
| `search` | 搜索结果中点击商品 | item_id、query | 搜索意图 |

所有事件都要带的公共属性：`user_id`（登录后的会员号；未登录用 device_id，登录后上报映射关系）、毫秒时间戳、`market`/站点、平台、App 版本、语言。

## 2. SPM 坑位编码

格式：`A$##$B$##$C$##$D`，依次是 **应用 $##$ 页面 $##$ 区块 $##$ 位置（从 0 开始）**。前三段决定请求路由到哪个栏位。

| 场景 | SPM（前三段） | 栏位 | 位置 D |
|---|---|---|---|
| 首页猜你喜欢 | `cdf$##$home$##$feed` | home_feed | 信息流中的序号 |
| 商品详情页 · 相关推荐 | `cdf$##$item$##$related` | item_related | 模块内的序号 |
| 购物车 · 凑单推荐 | `cdf$##$cart$##$bundle` | cart | 模块内的序号 |
| 支付成功页 · 买了还买 | `cdf$##$paid$##$bundle` | （P2） | |
| 搜索无结果页 · 兜底推荐 | `cdf$##$search$##$empty` | （P2） | |
| 离岛专区 | `cdf$##$island$##$feed` | （P2） | |

非推荐流量（运营位、搜索结果）也要上报 SPM，这样才能分清哪些转化来自推荐。

## 3. 归因字段

- 推荐接口返回的每个商品都带 `transData`（透传串）和 `request_id`。客户端在曝光、点击、加购、下单事件里**原样回传**这两个字段。
- 加购和下单如果发生在购物车页，引擎会按 last-click 在 72 小时内回溯归因，但前提是点击事件带了 request_id。
- 客户端如果对推荐结果做了二次处理（比如插入广告、截断），要调用 `/predict/api/{app}/callback` 回传实际展示的列表。

## 4. 质量要求（数据质量门禁会自动检查）

| 指标 | 要求 |
|---|---|
| 必填字段空值率 | < 1% |
| 行为中的 item_id 能在商品表找到 | ≥ 95%（低于 99.9% 会告警） |
| 未注册的事件类型 | < 5% |
| 时间戳异常（早于 2015 年或晚于当前时间） | < 0.1% |
| 重复事件 | < 2% |
| 整体 CTR | 在 0.2% – 50% 之间（超出范围通常说明曝光上报有问题） |
| 每日数据量环比变化 | < 60% |

## 5. 历史数据交付

- 格式：JSONL / CSV / Parquet 都可以，按天分文件。时区要说明清楚：本地时间要注明时区，或直接给 UTC/epoch。
- 时间范围：近 6–12 个月的行为数据，加上当前全量的会员、商品、门店价格和库存。
- 交付后我们会写好字段映射文件，执行 `recsys backfill`，然后输出两份报告：**回灌报告**（行数核对、丢弃原因、未映射的取值）和**数据质量报告**。之后再执行 `recsys baseline`，输出**离线基线报告**。
